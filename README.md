# Учебная задача «Анализ сайта»: СберАвтоподписка

Модель предсказывает вероятность того, что посетитель сайта совершит целевое действие
(оставит заявку, закажет звонок, откроет диалог и т. п.), и отдаёт ответ через HTTP API.

**Результат:** ROC-AUC **0.717** на отложенной выборке при ориентире 0.65 из брифа.
Бейзлайн даёт 0.50, логистическая регрессия 0.69.

## Состав проекта

| Файл | Назначение |
|---|---|
| `Анализ_сайта_СберАвтоподписка.ipynb` | аналитический отчёт: очистка, EDA, ML, выводы |
| `features.py` | очистка и фиче-инжиниринг, общий модуль для ноутбука, обучения и API |
| `train_model.py` | обучение модели из исходных csv и сохранение артефакта |
| `api.py` | FastAPI-сервис |
| `model/sber_auto_model.pkl` | обученный пайплайн вместе с метаданными |
| `requirements.txt` | зависимости |

Исходные данные (`ga_sessions.csv` и `ga_hits.csv`, около 4.4 ГБ) в репозиторий не входят.
Чтобы перезапустить ноутбук или обучение, положите их в папку `data`.
Обученная модель лежит в репозитории, поэтому API работает сразу после клонирования.

## Установка

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск API

```bash
uvicorn api:app --host 0.0.0.0 --port 8000
```

Интерактивная документация: <http://localhost:8000/docs>

### Эндпойнты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/status` | проверка, что сервис поднялся |
| GET | `/version` | метаданные модели: версия, дата, метрики, порог |
| POST | `/predict` | предсказание по одному визиту |
| POST | `/predict_batch` | предсказание по списку визитов, до 10000 за запрос |

### Пример запроса

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "9055434745589932991.1637753792.1637753792",
    "client_id": "2108382700.1637753791",
    "visit_date": "2021-11-24",
    "visit_time": "14:36:32",
    "visit_number": 1,
    "utm_source": "ZpYIoDJMcFzVoPFsHGJL",
    "utm_medium": "banner",
    "utm_campaign": "LEoPHuyFvzoNfnzGgfcd",
    "utm_adcontent": "vCIpmpaGBnIQhyYNkXqp",
    "utm_keyword": "puhZPIYqKXeFPaUviSjo",
    "device_category": "mobile",
    "device_os": "Android",
    "device_brand": "Huawei",
    "device_screen_resolution": "360x720",
    "device_browser": "Chrome",
    "geo_country": "Russia",
    "geo_city": "Zlatoust"
  }'
```

Ответ:

```json
{
  "session_id": "9055434745589932991.1637753792.1637753792",
  "prediction": 0,
  "probability": 0.011827,
  "threshold": 0.066080
}
```

`prediction` это 0 или 1, `probability` - вероятность целевого действия,
`threshold` - порог, при котором вероятность превращается в класс.
Обязательные поля только `visit_date` и `visit_time`, остальные можно не передавать:
пропуск обрабатывается так же, как отсутствующее значение в обучающих данных.
Неизвестные значения категорий (новая рекламная кампания, новый город) не ломают сервис.

## Переобучение модели

Положите `ga_sessions.csv` и `ga_hits.csv` (либо `.pkl` версии) в папку `data` и запустите:

```bash
python train_model.py --data-dir ./data --out ./model/sber_auto_model.pkl
```

`ga_hits` весит около 4 ГБ и читается потоково, пик потребления памяти около 2.5 ГБ.
Полный цикл занимает примерно минуту на 4 ядрах.

## Как устроено решение

1. **Целевая переменная.** По `ga_hits.event_action` собирается множество визитов,
   где было хотя бы одно из восьми целевых действий. Доля таких визитов 2.7 %.
2. **Очистка.** Удаляется `device_model` (заполнен на 0.9 %), скрытые пропуски GA
   (`(not set)`, `(other)`) приводятся к NaN, дубликаты проверяются по `session_id`.
   Пропуски не удаляются: их наличие само по себе информативно.
3. **Признаки.** Из 17 полей визита получается 34 признака: время визита и день недели,
   номер визита, тип трафика (органика, платный, соцсети), флаги наличия utm-меток,
   разобранное разрешение экрана, восстановленная по бренду и браузеру ОС, гео-флаги.
4. **Модель.** LightGBM с нативной поддержкой категориальных признаков,
   упакованный в `sklearn.Pipeline` вместе с фиче-инжинирингом.
   Порог подобран по максимуму F1, так как при пороге 0.5 модель почти никогда не отвечает 1.
5. **API.** FastAPI загружает пайплайн один раз при старте.

## Производительность

Замеры на 4 ядрах, модель загружена в память:

| Сценарий | Время |
|---|---|
| один визит, `/predict` | около 15 мс |
| батч из 1000 визитов, `/predict_batch` | около 40 мс |

Требование брифа выполняется с большим запасом.
Сервис не хранит состояние между запросами, поэтому масштабируется
горизонтально через uvicorn --workers N или несколько экземпляров за балансировщиком
